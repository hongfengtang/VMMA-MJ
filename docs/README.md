## 3. 术语与三个层面的“成功”

| 术语 | 本项目中的含义 |
| --- | --- |
| 中控 / CC | 外部服务，提供身份、药品/计划、库存及结果接收接口；其服务端不在仓库 |
| 终端编号 / terminalId | 当前 VMMA 实例的业务身份，由本地配置和中控登记共同确定 |
| 药品 / medicineId | 中控识别药品的编号，不等同于物理储位 |
| 储位 / boxId / column | 中控返回的储位编号，当前转为整数后作为设备货道参数 |
| 系统 token | 终端初始化取得的凭证，保存在 `GlobalData` |
| 用户 token | 员工登录返回的凭证，保存在 `MainWindow.loginUser` |
| Vendout | 一个药品/储位任务；内部按 count 逐包执行四步设备动作 |
| ACK / 事件 | 命令确认与设备异步反馈；不是中控 HTTP 业务成功码 |
| 回写 | 设备流程结束后 POST 储位数量与状态到中控 |

**设备流程成功、客户端回写成功、实物对账完成是三个不同层面。** 当前新设备定制允许 STEP4 累计三次特定状态进入成功路径；不能把全部程序成功提示都解释为已经取得常规五项设备完成证据。

## 4. 已知功能范围

| 分类 | 当前范围 |
| --- | --- |
| 常规可达 | 员工编号登录、药袋双条码调剂、补药告警、库存分页、只读药品详情、主动登出 |
| 条件入口 | 初始化失败后进入系统参数；正常登录后的管理菜单没有接线 |
| 隐藏 / 未接线 | 库存搜索、批次取药按钮、`JPFunctions` 的紧急/临时/管理等菜单 |
| 仅模型或占位 | 密码、指纹/人脸/独立刷卡能力、补药/盘点/退药等历史标记 |
| 无自动闭环 | 本地登录倒计时、自动 token 刷新、持久化回写补传、整单取消与多柜隔离 |

界面按钮名称保留源码中的繁体中文，解释使用简体中文。源码链接用于追踪实现，字段表同时注明 Java 类型、业务用途和保留能力；概念 JSON 示例不是完整接口契约或可导入生产配置。

示例仅使用占位值。不得记录真实账号、内置口令、token、内部地址、患者资料或未经脱敏的截图/日志。对客户定制只描述实际执行路径，不改变实现、不评价需求合理性。
