# 操作手册

> 适用版本：`mj2` 分支，源码基线 `bbf189c`，2026-10-10。[项目首页](../README.md) · [架构](ARCHITECTURE.md) · [详细设计](DETAILED_DESIGN.md)

本手册只说明软件操作。药品核对、交接、设备维修和异常处置必须遵守医院制度及设备厂商规程；不要通过重复点击、改库或绕过互锁消除异常。

## 1. 部署准备

由授权维护人员确认 Java 8、图形桌面、中控服务地址与终端编号、当前终端所连接药柜的 TCP 地址和端口、现场账号权限，以及运行目录的读写权限。

源码使用 `sun.misc.BASE64Encoder/BASE64Decoder`，不能仅因 Maven 指定 Java 8 目标就认为 JDK 11/17/21 也能直接编译。生产终端应使用经部署方确认的 Java 8 环境。

部署目录至少包含经批准的可执行 JAR、`data/system.db` 和完整 `images/`。`logs/` 需要可写；`lib/` 的 Allatori 是构建依赖，不是启动 JAR 的必需外部目录。

```text
<运行目录>/
├── MMH-VMMA-1.0.jar
├── data/system.db
├── images/
└── logs/
```

这些路径按进程工作目录解析，不按 JAR 所在目录自动解析。启动前必须切到运行目录。首次部署使用经批准的配置库，不要复制其他终端的配置后直接连接真实设备。

## 2. 构建、启动与停止

### 2.1 从源码构建

在项目根目录执行：

```bash
java -version
bash mvnw -Dexec.skip=true package
```

Windows 使用 `mvnw.cmd -Dexec.skip=true package`。该命令跳过 Allatori 外部执行步骤，生成 `target/MMH-VMMA-1.0.jar` 等打包产物；默认跳过测试是现有 POM 的设置。正式混淆包的工具授权、classpath 和发布审批见 [项目首页](../README.md)。

IDEA 导入 `pom.xml`，Project SDK 与 Maven Runner 使用 JDK 8，启用 Lombok 所需注解处理。运行类为 `com.mmh.vmma.VmmaApplication`，Working directory 设为项目根目录；不要用空上下文测试代替桌面启动入口。

### 2.2 启动

在部署目录执行：

```bash
java -jar MMH-VMMA-1.0.jar
```

若直接使用项目根目录和 `target/` 的包，命令为 `java -jar target/MMH-VMMA-1.0.jar`。不要在设备正在调剂时另启第二个实例。

外部 YAML 可通过 `--spring.config.additional-location=file:./application.yaml` 加载；文件需要部署方提供。数据库/日志可按 Spring Boot 配置规则覆盖，终端和药柜网络参数则由本地配置表管理。

### 2.3 停止与重启的前提

停止前确认没有调剂进行中，已核对设备取货状态和中控结果，且操作人员已登出。使用授权的应用退出流程；界面无响应时由维护人员按现场规程处理，不能靠重启判断上一笔出药是否成功。

变更药柜或中控配置后，在完成上述核对的前提下重启应用，使初始化流程重新读取参数并建立连接。

## 3. 配置库、备份与升级

`data/system.db` 存放 `cabinet` 和 `control_center` 两项 JSON 配置。它不是本地药品库存库，不要直接编辑 BLOB，也不要执行旧版清理脚本来修复新版本异常。

默认日志为 `logs/vmma.log`，按 YAML 配置滚动。DEBUG/TRACE 或错误日志可能记录请求、身份或业务内容；故障材料应先脱敏，并保留受控原件用于现场追溯。

由维护人员执行升级时：

1. 停止受影响终端的业务，核对最后一笔调剂的实物、设备与中控记录。
2. 按正常流程退出，备份原发布 JAR、外部 YAML、完整 `images/`、`data/system.db` 和必要日志；若存在 SQLite 的 `-wal/-shm` 文件，采用一致性备份方式，不能只复制活跃主库。
3. 记录版本和配置摘要，替换经批准的新包；不要用源码仓库的配置库覆盖现场配置。
4. 从正确工作目录启动，检查初始化、登录和查询；设备动作验证只在批准的测试条件下进行。
5. 如需回退，先停止并核对新版本是否已产生业务动作，再恢复兼容的程序/配置；恢复本地文件不会回滚中控库存或实物出药。

## 4. 首次初始化与系统参数

启动先显示「正在初始化，請稍後……」，读取本地配置、连接设备、调用中控注册。正常情况下进入「請輸入員工編號」登录页。

缺少柜体或中控配置等初始化失败时，主窗口会转「系統參數設置」。**正常登录后的界面没有可达的管理按钮**；不要尝试通过删除配置、破坏网络或使用源码内置口令强行进入配置。

已由批准的维护流程进入配置页后：

1. 填写 `*用戶名稱`，这是终端显示的客户名称，不是员工登录账号。
2. 填写 `*終端編號` 和 `*中央控管URL`，必须与中控登记及现场分配一致。
3. 首次增加设备连接时打开「新增端口」，选择 `TCP/UDP` 和 `TCP/UDP Client`，填写维护人员提供的「服務IP」「連接端口」。
4. 按「保存」，核对终端、中控和端口记录。没有明确整体成功弹窗；如出现错误，须重新检查两份配置是否均已保存。
5. 初始化失败路径按「退出」会提示「配置修改保存后，請重啟系統!」并结束应用；从正确工作目录重新启动。

当前实际支持的是 TCP Client，不是 UDP、串口或 TCP Server。默认 `127.0.0.1:20000` 只是重置值，不能照抄为现场药柜地址；配置多条端口也不代表具备多柜独立连接能力，当前应按已验收的单设备连接方案部署。

修改已有端口先选择记录，关闭新增开关后「保存」更新；「刪除」须选行并确认。**不要在表格排序后直接更新/删除**，当前视图索引处理存在风险。保存前由维护人员自行检查 IPv4、合法端口范围和 HTTP(S) URL，不能完全依赖界面验证。

保存只写本地数据库，不热更新当前连接和全局参数；成功初始化后从配置页「退出」也不是可靠的返回菜单路径。后续配置变更应在暂停业务并完成对账后，按现场批准的维护流程退出、修改并重启。

## 5. 登录、登出与软键盘

输入由医院授权的员工编号，按 Enter 或「確認」。中控认可后直接进入调剂页；红色提示显示中控拒绝原因时，应核对编号或联系维护人员。

本版没有账号密码输入步骤，不提供密码修改、人脸、指纹或独立刷卡采集。键盘模拟输入设备可以向文本框输入字符，但其安装方式与自动 Enter 行为需现场确认。

登录页软键盘通过 AWT Robot 向当前焦点发送系统按键；先确保员工编号框有焦点。「Delete」实际为退格，Shift 是切换式状态，使用后注意关闭，避免影响后续条码输入。图形桌面和系统键盘权限需现场配置。

调剂页页头「退出」是**登出**，会回登录页，程序继续运行。工作结束或离开终端必须主动登出；不能依赖自动闲置登出，本版没有执行该计时逻辑。

确需结束程序时，先完成调剂与对账、登出，再使用登录页右上角无文字退出按钮；鼠标移入会显示退出图标。它结束进程，与调剂页「退出」不同。

## 6. 双条码调剂

### 6.1 输入与开始

**开始前按医院规程核对药袋、条码归属和终端。按「確認」或在上方条码框按 Enter 后，系统会查询计划并自动出药，没有第二次出药前确认。**

1. 在「藥袋下方條碼」输入或扫描药袋下方条码。
2. 按 Enter，把焦点移到「藥袋上方條碼」。
3. 输入或扫描同一药袋的上方条码。
4. 核对两个输入正确后，按 Enter 或「確認」开始。输错且尚未开始时按「清除」重新输入。
5. 读取失败或「沒有待取藥物列表」时，先核对两段输入和中控计划，不要连续提交。

扫描枪是否自动发送 Enter、药袋版式及硬件驱动不在源码定义范围。因为上方 Enter 就会启动，请在第一次使用前由维护人员确认扫描行为。

### 6.2 自动执行期间

有计划时打开「調劑操作確認」，显示药品、单位、储位、计划量与库存、批号/效期、患者及处方相关字段。窗口显示后自动执行，「確定」先禁用，不是出药前批准按钮。

等待设备与界面反馈，不重复扫描、不另起实例，也不要通过关闭程序中止设备动作。界面没有可靠的整单取消按钮；某个储位失败后，其他已排队任务仍可能继续。

「正在取第 N 包」是尝试进度，不是成功确认。多药品图片可能仍显示首项，核对时应结合文本字段、处方及院方规程，不能单凭图片。

如显示计划量大于库存、出货失败或其他异常，立即通知授权人员按现场规程处理；当前客户端库存提示并非可靠硬阻断，不能以提示出现就认定设备没有动作。

### 6.3 完成与对账

全部储位有终结反馈后，窗口启用「確定」并尝试回传中控。核对设备反馈、界面异常、中控记录和实物，再按「確定」关闭，返回调剂页后可处理下一笔。

**「確定」可点击不等于回写成功；最后一项成功提示也不等于整单所有储位都成功。** 网络或回写异常时，本版没有可靠的回写重试按钮或持久化补传。

失败储位上报的数量仅代表此前被软件确认完成的包数；超时当前包仍可能已经出药。必须由授权人员核对并处置，不能重扫整单“补取”，也不能用重启或恢复本地数据库回滚结果。

## 7. 告警、库存与药品详情

### 7.1 调剂页补药提示

调剂页显示中控 `isAlarm` 标记的药物编号、药名、警示量和现存总量。告警行用于提醒维护/补药人员，不是本页执行补药的入口。

该列表在调剂页重新显示时查询，不是实时持续采样。使用翻页按钮查看更多记录；若用页码框和 `Go`，只输入显示范围内的有效正整数。

### 7.2 即时药存量

1. 调剂页按「即時藥存量」。
2. 查看储位号、药名、现存总药量、储位现存量、最大量、药物编号。
3. 使用 `|<<`、`<`、`>`、`>>|` 翻页，或输入有效页码后按 `Go`。
4. 选择需要查看的储位行，按「詳情」。
5. 查看只读药品/单位/包装/管制类型、所选储位的现存量和最大量、图片及告警提示。
6. 详情「返回」关闭；库存页「返回」回调剂。

同一药品有多个储位时分行显示，药品总量会重复；不要把这些重复总量相加。告警主要是药品级标记；排序后颜色可能错位，不能只依据颜色判断某个储位是否不足。

「即時」表示从中控读取；进入页面才重新查询，翻页和详情返回通常使用内存结果。药品学名等字段可能没有填充，部分接口字段没有详情控件。

搜索栏和「批次取藥」入口当前隐藏，不列为可执行操作。本页和详情没有编辑库存、确认补药、开门、盘点或退药功能。

## 8. 常见异常处理

| 情况 / 提示 | 处理与边界 |
| --- | --- |
| 缺少柜体或中控配置 | 授权维护人员检查配置库，完成配置后重启；勿执行旧业务建表脚本 |
| 初始化长期停留 / 失败 | 检查工作目录、数据库/JSON、地址端口和日志；显示启动成功也不能代替设备就绪确认 |
| 登录拒绝 | 按中控消息核对员工编号/授权；请求异常联系中控维护 |
| 「讀取取藥訊息錯誤」 | 核对双条码和中控服务，确认是否进入过出药窗口再决定后续处置 |
| 「沒有待取藥物列表」 | 核对中控待取计划及历史结果，勿自行改处方或库存 |
| 「藥品櫃當前狀態為不可出貨狀態」 | 不继续提交新任务，由设备维护人员依厂商规程确认状态 |
| 「查詢販賣機狀態無迴應」 | 检查授权网络端点/设备连接；不是完整厂商故障诊断 |
| 「設置退幣動作無迴應」 / 「設置取貨動作無迴應」 | 准备阶段缺少所需确认/事件，联系设备维护与系统管理员 |
| 「取貨動作無迴應」 / 出货失败 | 当前包可能已经落药，必须核对实物与中控，禁止盲目重取 |
| 「系統執行命令報錯」 / 「無法識別返回碼」 | 记录时间、储位和已完成数量，由维护人员排查，不假设会自动重试 |
| 结果回写失败 / 提示联系管理员 | 物理动作与后台记账可能不一致，没有自动补传；按授权对账流程处理 |
| 对话框一直无法按「確定」 | 无独立自动取消/恢复按钮；不要强制把本单当失败，交维护人员处理 |
| 告警库存或详情缺值 | 通知维护人员核对中控数据；本客户端不能完成补药或库存修正 |

出货阶段的 30 秒是等待进展阈值，不是全单硬期限。CONNECTED 只表示连接层状态，不保证允许出货。维护人员收集故障时间、终端/储位标识、界面消息、中控处理结果和必要日志，全部材料按医院要求脱敏。

设备急停、开柜、清障、断电、补药和安全门处理由厂商及医院 SOP 规定，本手册不提供绕过互锁、原始报文控制或直接改库的恢复方法。

## 9. 本版不适用的操作

不要沿用历史 README 中“选病床/医嘱”“QRCode 临时取药”“紧急取药”的步骤。当前常规界面是双条码调剂；批次入口隐藏，功能菜单未接线，退药、补药、盘点和自动闲置登出没有完整执行流程。

底层类、菜单常量、图片或 `application-return.yaml` 的存在不能证明上述操作已可用。需要新增这些功能时必须完成开发、权限与设备/中控联调，不应由操作人员直接开启隐藏入口。
